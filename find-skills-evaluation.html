01

What the supplied skill actually does

The attached find-skills file is a playbook for an AI agent—not the search engine or installer itself. It tells the agent when to search, how to shortlist, and what to show you.

Discover

Translate the need

Identify the task and keywords; inspect skills.sh before running the CLI.

Search

Find candidates

Run npx skills find; narrow with terms or an owner.

Screen

Check evidence

Review install counts, source maintainer, repository, and the skill contents.

Decide

Present, then ask

Explain fit and link; ask before installing. The interactive find flow can install as soon as a result is selected.

Important distinctionThe discovery skill says to check installs, author reputation, and stars. Those are triage signals—not a security audit, accuracy test, or guarantee the skill fits our agent.

03

How the CLI’s steps differ

It is easy to assume “find” is always search-only. The current CLI has distinct paths: a query/non-TTY search prints candidates, while the interactive TTY flow lets you search and then can install the selected skill.

CommandWhat it doesOperational effect
skills findA query searches the directory and prints matches; optional --owner scopes the search. Starting without a query in an interactive TTY opens the search prompt; choosing a result can immediately call the installer.Query/non-TTY search is discovery only. Interactive selection installs the chosen skill; do not assume every use of find is read-only.
skills add … --listRetrieves a source repository and displays its available skills.Inspection step; tested here without installing a skill.
skills add … --skill NAMEInstalls selected skill files for agent(s).Writes into project or user-level agent skill folders; default can be project scope.
skills use …Builds a prompt using a selected skill without a persistent installation; may launch a supported agent.Still retrieves the source and passes its instructions into an AI workflow. “Not installed” does not mean “trusted.”
skills update / removeRefreshes or removes installed skills.Updates can change instructions; review changes before relying on them.
# Explicit, scoped install after review (example only) npx skills add vercel-labs/agent-skills \\ --skill vercel-react-best-practices \\ --agent codex # Global installs affect more projects; use only when intended npx skills add vercel-labs/agent-skills \\ --skill vercel-react-best-practices -g

The current CLI help supports --skill, --agent, --global, and --yes. For first-time use, avoid --all and auto-confirm flags; make scope explicit.

04

What can go wrong—and how to reduce it

A skill is instruction content consumed by an agent. It may include supporting files or scripts. Even if the installer only copies or links files, the agent can later follow instructions that invoke tools, read files, or make changes.

RiskWhy it mattersControl
Popularity mistaken for trustInstall count and stars measure attention, not correctness, maintenance, or benign intent.Open the exact source repository and inspect the actual skill files. Verify advice against authoritative docs.
CLI package supply chainnpx skills … runs the Skills CLI package; on this machine npx fetched skills@1.7.2 before the search. This is a separate trust step from the skill being considered.Use the official CLI source, review the package/version under your organization's dependency policy, and run with least privilege.
Find may install interactivelyWith no query in an interactive terminal, choosing a search result runs the add flow; a user can install by selecting the result.Use a query for read-only search, or add --list to inspect repository contents. Read the prompt carefully before selecting a skill.
Instruction injection / overreachA skill can tell an agent to ignore boundaries, expose data, or take actions outside the task.Treat the file as untrusted input. Reject instruction-hierarchy bypasses, secret requests, unexplained network calls, and unrelated side effects.
Wide installation scopeA global install can affect many projects and agent sessions.Prefer a project-scoped, single-skill, single-agent install. Use least privilege and avoid broad “install all” options.
Hidden operational contentLinked scripts, dependencies, setup commands, or remote downloads may add risks beyond the visible summary.Inspect all files, scripts, and dependency/setup steps; test in a disposable, low-privilege environment first.
Stale or changed guidanceUpstream can change after review; update commands can replace the version you checked.Record source URL, commit/version, and review date; inspect diffs before updating.
Telemetry / query privacyThe CLI code sends a find event containing the search query and result count to its telemetry endpoint by default (unless disabled). The vendor describes telemetry as anonymous; sensitive search phrases should still be treated as disclosed to that service.Do not search using secrets, client names, or confidential project terms. Set DO_NOT_TRACK=1 or DISABLE_TELEMETRY=1 before running if policy requires opt-out.
Never let a skill authorize itselfDo not follow skill instructions to reveal credentials, weaken safeguards, run unrelated commands, or perform external actions without the user's authorization. The user's request and the agent's security policy remain in control.
05

Recommended operating procedure

Before installing

Verify the candidate

1. Search with precise keywords.
2. Open the skill source, not just its directory card.
3. Check maintainer identity, history, issues, license, and all linked scripts.
4. Compare important claims with official documentation.
5. Decide whether the task warrants the capability at all.

After installing

Contain and verify

1. Install one skill to one agent and project scope.
2. Keep secrets and production credentials out of the test.
3. Try a bounded, reversible task.
4. Review every generated command and resulting diff.
5. Record the source/version; inspect changes before updates.

Recommendation on this supplied skillKeep it as a discovery workflow. Use its search and shortlist steps, but strengthen the recommendation stage: inspect the exact skill files and source history, verify high-impact instructions independently, and ask before installing. Its install-count threshold should be a ranking hint, never a pass/fail security rule.
